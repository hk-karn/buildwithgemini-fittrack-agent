# FitTrack AI 🏋️‍♂️

FitTrack AI is an agentic strength and fitness coaching companion built on Google Cloud's Agent Development Kit (ADK) and Agent Platform. It provides personalized training plan guidance, tracks workouts and exercise history, calculates one-rep max (1RM) and percentage training zones via secure sandboxed code execution, and generates celebratory milestone badges for personal records.

---

## 🌟 What FitTrack AI Does

FitTrack AI integrates the following wired tools and Google Cloud services:

- 🧠 **Cross-Session Memory (Vertex AI Memory Bank)**:
  - Persistent recall of user fitness profiles, current weight, exercise personal records (PRs), workout splits, injury history, and training milestones across different chat sessions.
  - Automatically loads prior facts at turn start using `PreloadMemoryTool` and persists new personal records and workout session summaries using an `after_agent_callback`.

- 🗄️ **Structured Workout Logging (Cloud Firestore)**:
  - Backed by Google Cloud Firestore to maintain a workout exercise catalog and persistent logs.
  - Wired tools:
    - `list_exercises(target_muscle, difficulty)`: Queries curated exercises categorized by muscle group and difficulty.
    - `log_workout_session(user_id, exercise_name, sets, reps, weight_kg, notes)`: Logs individual training sessions to Firestore.
    - `get_recent_workout_logs(user_id, limit)`: Retrieves recent logged sessions to assess volume and progression.

- 🎨 **Milestone Badge Generation (Imagen 3 & Cloud Storage)**:
  - Uses `gemini-3.1-flash-lite-image` in the global region to generate high-quality achievement badge artwork when users break personal records.
  - Saves the generated bytes directly to the session artifact store for inspection.
  - Uploads the image bytes to a public Google Cloud Storage bucket (`fittrack-agent-media-<PROJECT_ID>`) and returns the public HTTPS URL for inline viewing.

- 🧪 **Safe Code Sandbox (Agent Platform Code Execution)**:
  - Wired via `AgentEngineSandboxCodeExecutor` to safely execute Python code in an isolated Vertex AI Reasoning Engine sandbox environment.
  - Accurately calculates 1RM using standard formulas (e.g., Epley / Brzycki), warm-up weight ladders, working percentage zones (50%–90%), and volume metrics without LLM math hallucinations.

- 🪟 **Agent-to-User Interface (A2UI v0.8 Basic Catalog)**:
  - Uses the A2UI framework to render responses as structured display cards (`Card`, `Column`, `Row`, `Text`, `Image`, `Icon`) in both the ADK playground and the custom frontend rather than plain markdown.
  - Emits A2UI data blobs via an `after_model_callback` (`a2ui_callback`).

- 🌐 **Web Chat Frontend (FastAPI & Cloud Run)**:
  - Lightweight FastAPI proxy and HTML5 chat interface in `frontend/` that speaks the A2A protocol.
  - Styled with a modern dialogue layout featuring speaker avatars (`🏋️` Coach vs. `👤` You), quick-prompt chips, and a built-in client-side A2UI renderer.

*(Note on planned features: matplotlib volume trend charts from project brief are planned for future releases).*

## 🚀 Running the Project Locally

### 1. Prerequisites

- Python 3.11+
- [uv](https://docs.astral.sh/uv/) package manager
- Google Cloud SDK (`gcloud`) authenticated with your project:
  ```bash
  gcloud auth login
  gcloud auth application-default login
  gcloud config set project <YOUR_PROJECT_ID>
  ```

### 2. Local Agent Playground

Run the ADK agent playground with Memory Bank integration:

```bash
# Navigate to the agent directory
cd fittrack-agent

# Install dependencies
uv sync

# Launch the playground with memory service enabled
uv run adk web . --port 8080 --reload_agents --memory_service_uri=agentengine://projects/<YOUR_PROJECT_ID>/locations/<LOCATION>/reasoningEngines/<REASONING_ENGINE_ID>
```

### 3. Local Web Frontend

To run the custom chat UI proxy locally against a deployed Agent Runtime:

```bash
cd fittrack-agent/frontend

# Install frontend dependencies
pip install -r requirements.txt

# Configure environment variables
export AGENT_ENGINE_RESOURCE_NAME="projects/<PROJECT_NUMBER>/locations/<LOCATION>/reasoningEngines/<REASONING_ENGINE_ID>"
export AGENT_DIRECTORY="app"

# Start the frontend server
python3 main.py
```

Open a browser to port `8080` to interact with your agent.

## ☁️ Deployment

### 1. Deploy Agent to Agent Platform

Deploy the agent logic to Vertex AI Agent Runtime:

```bash
cd fittrack-agent
agents-cli deploy --no-confirm-project
```

### 2. Deploy Frontend to Cloud Run

Deploy the web frontend container to Cloud Run:

```bash
cd fittrack-agent/frontend
gcloud run deploy fittrack-frontend \
  --source . \
  --region us-east1 \
  --set-env-vars="AGENT_ENGINE_RESOURCE_NAME=<YOUR_REASONING_ENGINE_RESOURCE_NAME>,AGENT_DIRECTORY=app" \
  --allow-unauthenticated
```

Grant the Cloud Run service account permission to call the Reasoning Engine:

```bash
gcloud projects add-iam-policy-binding <YOUR_PROJECT_ID> \
  --member="serviceAccount:<CLOUD_RUN_SERVICE_ACCOUNT>" \
  --role="roles/aiplatform.user"
```
